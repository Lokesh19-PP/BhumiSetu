# 07. REST API Documentation — Bhumisetu (भूमिसेतू)

> **Academic Year:** 2026–27  
> **Project Title:** Bhumisetu: AI-Enabled, GIS-Based Integrated Land Information & Single-Window Land Service Platform  
> **Tagline:** *"One Parcel. One Window."*  

---

## What This Document Covers

This document provides complete technical documentation for the Bhumisetu RESTful Web API. It includes an endpoint catalog grouped by functional subsystem, details the HTTP methods, paths, authorization requirements, request/response models, and presents three comprehensive, realistic request/response JSON payloads. It also references the interactive OpenAPI/Swagger UI console available in the live application.

---

## 1. Interactive Swagger UI Reference

Bhumisetu automatically exposes interactive OpenAPI 3.0 documentation generated by `springdoc-openapi-starter-webmvc-ui:2.6.0`:

* **Swagger UI URL:** [`http://localhost:8080/swagger-ui/index.html`](http://localhost:8080/swagger-ui/index.html) (or [`http://localhost:8080/swagger-ui.html`](http://localhost:8080/swagger-ui.html))
* **OpenAPI Raw JSON Specification:** [`http://localhost:8080/v3/api-docs`](http://localhost:8080/v3/api-docs)

The Swagger console allows examiners and developers to test all endpoints interactively, inspect schemas, and supply Bearer JWT tokens via the *"Authorize"* dialog.

## 2. API Endpoint Catalog

### 2.1 Authentication & User Endpoints (`/api/auth`)
*Controller:* [`AuthController.java`](file:///backend/src/main/java/in/bhumisetu/controller/AuthController.java)

| Method | Endpoint Path | Role Required | Request Body | Response Type | Purpose / Description |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `POST` | `/api/auth/login` | Public | `LoginRequest` (email, password) | `AuthResponse` | Authenticates credentials and returns signed JWT with user profile and role. |
| `POST` | `/api/auth/register` | Public | `RegisterRequest` (fullName, email, password, phone) | `AuthResponse` | Creates a new Citizen account and returns an authenticated JWT session. |
| `GET` | `/api/auth/me` | Authenticated | None | `UserDto` | Retrieves the profile and role details of the currently authenticated user. |

### 2.2 GIS & Land Parcel Endpoints (`/api/parcels`)
*Controller:* [`ParcelController.java`](file:///backend/src/main/java/in/bhumisetu/controller/ParcelController.java)

| Method | Endpoint Path | Role Required | Request Body | Response Type | Purpose / Description |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `GET` | `/api/parcels` | Public | None (`?q=` query param) | `List<ParcelSummaryDto>` | Searches parcels matching Survey Number, ULPIN, or Village. |
| `GET` | `/api/parcels/geojson` | Public | None | `GeoJsonFeatureCollection` | Streams all cadastral parcel polygons as GeoJSON for Leaflet rendering. |
| `GET` | `/api/parcels/{id}` | Public | None | `ParcelSummaryDto` | Retrieves high-level metadata for a specific parcel by numeric ID. |
| `GET` | `/api/parcels/by-ulpin/{ulpin}` | Public | None | `ParcelSummaryDto` | Looks up a parcel by its 14-character ULPIN. |
| `GET` | `/api/parcels/by-survey/{surveyNumber}` | Public | None | `ParcelSummaryDto` | Looks up a parcel by village Survey/Gat Number. |
| `GET` | `/api/parcels/{id}/dossier` | Public | None | `ParcelDossierDto` | Aggregates the 360-degree dossier (ownerships, documents, applications). |
| `GET` | `/api/parcels/by-ulpin/{ulpin}/dossier` | Public | None | `ParcelDossierDto` | Retrieves complete parcel dossier queried directly by ULPIN. |
| `GET` | `/api/parcels/spatial/point` | Public | Params: `lat`, `lon` | `ParcelSummaryDto` | Point-in-polygon lookup identifying the parcel polygon enclosing coordinates. |
| `GET` | `/api/parcels/spatial/bbox` | Public | Params: `minLon`, `minLat`, `maxLon`, `maxLat` | `List<ParcelSummaryDto>` | Bounding box spatial query returning parcels overlapping a viewport. |

### 2.3 AI Document & OCR Endpoints (`/api/documents`)
*Controller:* [`DocumentController.java`](file:///backend/src/main/java/in/bhumisetu/controller/DocumentController.java)

| Method | Endpoint Path | Role Required | Request Body | Response Type | Purpose / Description |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `POST` | `/api/documents/upload-ocr` | Authenticated | `multipart/form-data` (`file`, optional `parcelId`) | `OcrResultDto` | Uploads scanned land record, runs Tesseract OCR, parses cadastral entities, and returns confidence scores. |
| `PUT` | `/api/documents/{id}/verify` | Authenticated | `VerifyDocumentRequest` (metadata, verified flag) | `DocumentDto` | Confirms/edits OCR metadata and confirms permanent parcel association. |
| `GET` | `/api/documents/parcel/{parcelId}` | Public | None | `List<DocumentDto>` | Lists all verified and uploaded documents associated with a parcel. |
| `GET` | `/api/documents/{id}` | Public | None | `DocumentDto` | Retrieves document metadata, storage path, and full OCR text by ID. |
| `GET` | `/api/documents/sample` | Public | None | `Map<String, Object>` | Returns pre-packaged sample 7/12 extract details for instant 1-click viva demo. |
| `GET` | `/api/documents/search` | Public | Params: `q`, `documentType`, `village`, `verifiedOnly` | `List<DocumentSearchResultDto>` | Full-text smart search across OCR digitized text with snippet highlighting. |

### 2.4 Single-Window Application & Workflow Endpoints (`/api/applications`)
*Controller:* [`ApplicationController.java`](file:///backend/src/main/java/in/bhumisetu/controller/ApplicationController.java)

| Method | Endpoint Path | Role Required | Request Body | Response Type | Purpose / Description |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `POST` | `/api/applications` | Authenticated (`CITIZEN`, `ADMIN`) | `CreateApplicationRequest` | `ApplicationDto` | Submits single-window land application and automatically routes to department. |
| `GET` | `/api/applications/my` | Authenticated (`CITIZEN`, `ADMIN`) | None | `List<ApplicationDto>` | Lists all applications submitted by the logged-in citizen. |
| `GET` | `/api/applications/{id}` | Authenticated | None | `ApplicationDto` | Retrieves full application details, parcel data, and workflow timeline. |
| `GET` | `/api/applications/track/{appNumber}` | Public | None | `ApplicationDto` | Public tracking endpoint to view application status and decision history by reference number. |
| `GET` | `/api/applications/officer/queue` | Officers & Admin (`PLANNING_OFFICER`, etc.) | None (`?status=` optional filter) | `List<ApplicationDto>` | Lists pending applications filtered by the officer's department. Citizens are forbidden (`403`). |
| `POST` | `/api/applications/{id}/decision` | Officers & Admin (`PLANNING_OFFICER`, etc.) | `OfficerDecisionRequest` (action, remarks) | `ApplicationDto` | Officer approves, rejects, or requests information. Citizens are forbidden (`403`). |

## Key Takeaways

1. **22 Documented Endpoints:** Spans Authentication, GIS Cadastral queries, OCR Document Digitization, Single-Window Workflow routing, and System Administration.
2. **Interactive Swagger Console:** Automatically generated from code annotations at `http://localhost:8080/swagger-ui/index.html`.
3. **Strict Role Constraints:** Officer actions (`/decision`, `/officer/queue`) and admin operations (`/admin/*`) are strictly enforced via `@PreAuthorize`.
4. **Structured JSON Payloads:** All endpoints utilize strong typing with predictable DTO schemas, clear validation constraints, and standardized date-time formatting.
5. **Real-world Request Samples:** Provides full JSON payloads for authentication, OCR metadata extraction with confidence metrics, and application workflow initialization.
